## 🔄 文档同步更新

请按 Agora 项目 `AGENTS.md` R12（文档同步铁律）执行：

### 第一步：确定同步范围
1. 如果用户提供了决策内容，记录决策摘要，定位涉及的文档。
2. 如果用户未提供，检查最近提交（`git log --oneline -5`）与 `docs/task-status.json` 的 `last_updated` 判断最近变更范围。
3. 自动扫描关联文档，列出受影响清单。

### 第二步：执行同步（按权威顺序）
1. **项目蓝图**（决策定稿）：涉及重大架构决策 → 更新 §21 已定决策段，打 `[YYYY-MM-DD 架构决策更新]` 标记。
2. **详细设计方案**（落码规格）：涉及接口/schema/流程 → 定位对应章节修改（§1 State / §2 角色 / §3 编排 / §4 抢占 / §5 通信 / §6 执行器沙箱 / §7 投影 / §8 多租户 / §9 阶段 0 切片）。
3. **系统架构设计文档**：涉及分层/模块/韧性表 → 同步 L1-L4 映射与关键路径描述。
4. **技术选型文档**：涉及选型或版本 → 更新对应小节 + §12 依赖锁定 + §13 决策记录。
5. **开发计划安排**：涉及排期/任务拆分 → 更新对应 Phase 章节；如任务增删，**同步 task-status.json 的 phases/tasks**。
6. **框架调研与借鉴决策**：仅当决策推翻某条借鉴结论时更新，并注明原因。
7. **task-status.json**：新增/修改的常驻约束同步进 `standing_decisions`；更新 `last_updated`。
8. **AGENTS.md**：涉及红线或常驻决策变化 → 同步 §3 常驻决策表与 §4 红线。

### 第三步：一致性交叉检查
1. 修改完成后，grep 检查被替换的旧术语是否在其它文档残留（如当年 yieldSlot→终止并分叉的同步）。
2. 检查新术语在所有出现处口径一致。
3. 文档冲突或漂移发现后作为 GitHub Issue 记录，**不得写入 task-status.json**。

### 第四步：输出变更摘要
1. 列出所有修改的文件与位置、内容摘要。
2. 提示："✅ 文档同步完成。建议执行 `/commit-agora` 固化本次同步。"

> 铁律（R12）：有代码变更必须同步更新相关文档；所有新增或修改的内容用 `[YYYY-MM-DD 架构决策更新]` 或 `[YYYY-MM-DD 选型同步]` 标记开头，便于人工复核。
