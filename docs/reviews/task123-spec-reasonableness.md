## 1. 依据

相关原文：

> 不能证明授权根以外不受副作用时，相关 direct 写入不得启用，回到设计修订，不能仅通过“用户同意风险”放开既定越界保护。

> 已获宽写权限的活子进程不能靠修改 registry 缩权；要等其结束/按命令超时规则停止并证明无后代可写，再开新策略进程。

> 授权撤回先关闭新操作；在途按上述安全点/工具收敛结束，界面区分撤回请求和已生效，不声称立即中断 token。

> 不能声称抵御同 UID 恶意进程控制 Agora 本身或持续破坏用户文件。

前一句被测试解释为动态路径绝对边界，后三句却已经接受在途能力不能瞬时撤销、外部进程不受Agora完全控制。需要明确威胁模型与时序，不能让同一文档作两个相反承诺。

本机证据：[复核回执](task123-boundary-evidence/move-root-iOBZlW.json)。授权内打开的候选普通文件随项目根被移到outside后，重新openat返回EPERM，旧fd的pwrite/fsync成功，源target保持original。该探针只观察OS原语，没有registry、失效处理、收敛或正式文件事务服务。因此它揭示的是“不能依赖OS自动撤销旧fd”，**不能单凭它认定产品已经越权改写从未授权的外部文件，也不能据此认定产品已安全**。

标准背景：[POSIX rename](https://pubs.opengroup.org/onlinepubs/000095399/functions/rename.html)区分目录项变更与尚未关闭的文件引用；[POSIX设计说明](https://pubs.opengroup.org/onlinepubs/9799919799/xrat/V4_xbd_chap01.html)说明先写临时文件、同步、再rename的模式。它们支持区分路径和文件对象，不替代当前macOS Seatbelt行为的实测，也不证明任意新候选机制安全。

进一步核对探针源码：它在`F_GETPATH`显示位置变化、重新打开返回EPERM之后，**仍故意调用pwrite**以观察OS是否撤销旧fd。正式服务此时应停止下一写入。这说明原测试没有验证实际失效处理；它的失败不能直接推广为“所有符合契约的实现都会在发现漂移后继续写”。在最后检查之后已经进入OS的操作仍可能完成，因此也不能反过来用增加一次检查承诺瞬时撤销。

## 2. 逐项评审

| 项目 | 判断 | 修正或保留 |
| --- | --- | --- |
| 未授权文件/凭据隔离、禁网及受控下载 | 合理且必须 | 从未授权的外部哨兵必须不可读写，symlink/hardlink/替换路径不能引入新能力；不降低L02/L03/L04 |
| 根移动导致旧fd瞬时失效 | 不合理的隐含承诺 | 新准入检查与在途收敛分开；不把路径变化当内核会自动撤销文件对象能力 |
| 目录竞争时的成功判定 | 原文不够完整 | 漂移必须关闭绑定、使当前操作不再具有有效成功/交付资格；有副作用就记partial/recoveryRequired，不伪装无副作用失败 |
| 非合作外部编辑 | 现有保证合理 | 保留检测、冲突、版本保全；不承诺冻结任意同UID程序或文件内容CAS |
| 项目根内同卷事务区 | 尚无证据必须否定 | 保留现有方案与严格注册/隔离/清理条件；移动临时对象本身不等于取得未授权新对象 |
| 强制迁移到应用状态卷 | 上轮建议证据不足、代价偏大 | 不采用为当前方案；没有证明它解决所有目录/句柄竞态，却额外排除了另一APFS卷的项目 |
| 通过后置检查补救所有目录竞态 | 不合理 | 后置检查只能撤销成功资格、留证和保全；不能称为防止已发生的副作用。新对象越权仍需实际强制边界 |
| macOS15/26.5、新rename标志 | 原门禁合理 | 编译目标、SDK符号与实测能力分开，缺能力关闭；本轮不换最低系统或豁免验收 |
| 完整后代进程收敛 | 原门禁合理 | 不把单子进程close或PID/进程组当所有后代已停，L14仍待实测 |

## 3. 修订后的精确边界

### 3.1 威胁模型

- 模型参数、项目脚本及其后代是不受信方，必须受实际文件/进程/网络/IPC边界约束；不能由它们声明grant、fd身份或“文件之前授权过”。
- 用户和外部编辑器可非合作地修改/移动项目。系统保证检测后的关闭与在途保全，不宣称能控制宿主同UID恶意进程、管理员或瞬时撤销所有OS能力。
- 将受信registry/策略/helper篡改、凭据泄漏、访问从未授权的其他文件仍按真实安全失败处理。排除“宿主自身已被控制”的承诺不豁免项目代码攻击。

### 3.2 新访问与在途访问

新操作、新路径解析或重新打开文件须按当前授权revision、根/父链身份、写域epoch重新准入；不自动跟随移动路径，不以仍相同的路径字符串接受替换根。目录fd不能被当作递归访问其新父目录或新加入文件的永久能力。

受信服务已经合法打开并记录身份的**单个普通文件对象**，可在操作在途期间仍被OS允许访问。仅对原操作、原对象和原权限讨论这种情况；不是给用户源文件开写fd的许可，也不是根移动后故意继续工作。技术暂存对象、命令专用输出和只读输入须有不同用途与受信身份记录，不能仅凭相同内容hash或inode数字重建活权限。

### 3.3 发现漂移后的行为

1. 每次受信调用准入、准备进入下一有副作用步骤、返回成功/发布验证或交付之前都重核绑定；watcher仅作提前提示，不是唯一来源。不把检查之间的窗口说成已经消失。
2. 一旦发现根/父链或授权漂移，停止新准入和后续有副作用步骤；关闭自身fd/映射、收敛工具和后代。已提交给OS的写入可能完成，不能假报已撤销；项目进程不能通过旧授权取得新scope。
3. 如果竞争发生在最后一次检查之后，原已授权对象上的在途效果须被记录和保全；本次操作不作为当前绑定的有效成功/可信验证/交付。若此前已持久化成功事实，追加失效事实，不改写历史；旧实测事实可保留，但不能批准当前目录。
4. 待自身能力关闭、工具后代收敛、回执落盘之后才报告撤回完成/可安全编辑或回收。失败保持needsAttention；移动后的对象不能凭诊断路径自动追踪或递归清理。
5. 重新绑定仍需用户明确选择/确认；同一动作重试不能重新授予权限或重复破坏性应用。

不采用“任何非零退出即安全”的验收方法。未授权哨兵未变、用户版本保全、失败回执及无残余可写能力必须分别证明。

## 4. 验收与测试调整要求

当前原语探针的4通过/1失败、原始日志/源码hash及上轮报告均保留为历史，不改写成已通过。

L02/L06要区分：

| 场景 | 必要断言 |
| --- | --- |
| 从未授权的独立外部哨兵 | 所有攻击路径均不可读写，身份/内容不变；不能把它与移走的原候选文件混为同一对象 |
| 根/父链在新调用前已变化 | 受信端口拒绝、不跟随路径，无新副作用 |
| 原操作打开技术候选文件后根被移动 | 记录原对象身份；新打开被拒绝；原在途写可能已发生，服务检测后关闭能力、终止后续步骤、不产生有效applied/验证/交付、保全源文件及各版本 |
| 原路径被新根/外部链接替换 | 拒绝替代对象，外部哨兵不变；不从旧目录fd扩展权限 |
| 写入/交换后至返回成功之间漂移 | 成功资格失效，结果和回执如实包含已发生变化；不得自动回滚覆盖用户版本 |
| 撤回与清理 | 无旧fd/映射/后代活写者才闭合；无法证明则保留资源及needsAttention |

实现时必须补真实端口/事务生命周期测试。原测试中“OS必须自动使旧fd的pwrite失败”应作为错误规格假设的诊断记录，按本次审查修正测试目标；**不得仅反转一个expect就宣称L02/L06通过**。本轮先修正文档，不修改测试断言、测试匹配或任何产品代码。
